The platform ships with a full FastAPI backend and webhooks available from day one — no additional setup required.

<Tip>
  Webhooks fire on all state changes regardless of whether the change was made via the UI, API, or a third-party integration.
</Tip>

## Event reference

| Event | Trigger |
|---|---|
| `idea.created` | New idea submitted via any channel |
| `idea.status_changed` | Status updated by an admin or PM |
| `idea.merged` | Idea absorbed into another idea |
| `idea.voted` | User upvotes an idea |
| `roadmap_item.status_changed` | Roadmap item changes status |
| `announcement.published` | Announcement goes live to users |
| `changelog.published` | New changelog entry published |

## Example payload

All webhook payloads follow a consistent structure:

```json
{
  "event": "idea.status_changed",
  "timestamp": "2025-06-01T10:32:00Z",
  "data": {
    "id": "idea_abc123",
    "title": "Dark mode support",
    "previous_status": "planned",
    "new_status": "in_progress",
    "updated_by": "user_pm001"
  }
}
```

## Retries and delivery

- Webhooks are delivered via HTTP POST to your configured endpoint.
- Failed deliveries (non-2xx response) are retried with exponential backoff.
- The event log in the admin panel shows delivery status for every fired event.
